# SlabCalc — concrete estimating app (handoff brief)

Desktop app for a concrete contractor (driveways, walkways, patios). Scope: an estimate builder that ends in a good-looking 5-page, Hormozi-style proposal. **No CRM / pipeline / Pipedrive for now** — the owner says they're too small; keep the home screen a simple estimate list.

## Current state
`SlabCalc.html` is the whole UI (vanilla JS, no build step), wrapped in an Electron Mac app. All flows were click-tested 2026-11-15.
- Data: `localStorage` key `slabcalc.v1` (jobs + settings); photos in IndexedDB `slabcalc-photos`. JSON backup / import on the Estimates page — import **merges** jobs by id and only replaces prices if the file has `settings`. Backups include photos (`job.photos.before/after` data URLs, moved into IndexedDB on import), so a single-estimate file is self-contained. Data in the app is separate from data in Chrome — move it with backup/restore.
- Map: Leaflet 1.9.4 + Esri World Imagery tiles (no key). Address search via OSM Nominatim (the app sets a User-Agent).
- Leaflet and fonts are bundled in `vendor/` (generated by `npm run vendor`; HTML loads them by relative path).
- Proposal pages auto-shrink content (`fitPages()`) so nothing is clipped. In the app, **Save PDF** uses `printToPDF` via `window.slabcalc.savePDF` (`electron/preload.js`); in a browser it falls back to `window.print()`.

## Web version
`npm run web` (scripts/publish-web.sh) force-pushes `SlabCalc.html` (as `index.html`) + `vendor/` to the `gh-pages` branch, served at https://lukenukem89.github.io/SlabCalc/ . The repo is public for free Pages; keep customer data (`mockups/`) out of git. Browser data is per browser, separate from the Mac app.

## Commands
- `npm start` — run the app in development.
- `npm run dist` — build `dist/SlabCalc-<ver>-arm64.dmg` (ad-hoc signed, not notarized: first launch needs right-click → Open).
- Browser preview: `python3 -m http.server 8765` then open `http://localhost:8765/SlabCalc.html` (`.claude/launch.json` has this).

## Flow (hash routes)
1. `#/` **Estimates**: card list with site-plan thumbnails and totals, search (when >6), new / duplicate / delete.
2. `#/job/:id/questions` **Site questions**: what's there now, vehicle use, soil, slope, truck access, tie-ins. Drives thickness (4/5/6″), base depth (4–8″), dig depth, and a numbered customer-facing work plan (811, tear-out or reuse gravel, excavate, fabric, base, forms, rebar/dowels, pour, joints, cure, seal).
3. `#/job/:id/map` **Map & pours**: driveways/patios are polygons (click corners); **walkways are centerline paths + width** (`pour.path`, `pour.width`; `measurePath()` derives `pour.pts` and puts joints perpendicular to the path, spaced ≈ width, with a miter joint at bends > 20°). Drag vertices to edit. Polygons are **auto-squared** on finish (`squarePts()`: edges within 12° of the main axis snap to 0°/90°, angled ends stay) and can be set to an exact length/width (`setPourDim()`, keeps the slab centred); `pour.square` toggles this. The selected pour shows each side's length. "Concrete view" shows pours as finished panels in the chosen finish. Each pour gets area, perimeter, oriented-bounding-box L×W, and **auto control-joint layout**: max spacing = min(2.5 × thickness in ft, 15); panels near-square (length ≤ 1.25 × width); joints clipped to the polygon and drawn on the map. Live cost breakdown in the side panel.
4. `#/job/:id/photo` **Before / after**: upload a street photo, click the 4 corners of one slab (default: largest driveway); a homography (`job.photoFit`, `fitProjector()`; `bestRotation()` prefers the slab's long sides running into the picture, "Turn plan" to override) projects every measured pour, joint and finish texture into the photo in perspective. Old `job.trace` free-hand outlines still render.
5. `#/job/:id/proposal` **Proposal**: 5 letter-size pages, printed via `window.print()` → Save as PDF:
   cover (price + on-time badge; before/after photo or site plan) · scope with site plan, panel table and specs · process steps · price, bonuses with a sign-by date, 4 finish tiers, payment schedule, "measured remotely, confirmed on site within 5%" · optional **What's included** checklist page 5 (`job.includes` text: `# Group`, `- item` → ✓ lines; `parseTerms()`), typically the sub's inclusions rewritten for the customer — inclusions only, no sub terms or name · guarantee (20% back if not finished by the completion date, with day-for-day extensions for weather/changes/permits/hidden conditions) + workmanship warranty + signatures.
6. `#/job/:id/sub` **Sub request**: one-page request for a single lump-sum price from a subcontractor (`renderSubRequest`, data in `job.sub = {name, due, notes}`): address, satellite site plan, pour table, site conditions, turnkey scope (`subScopeItems()`: everything incl. 811 and required sealer — the owner subcontracts 100%), requirements (completion date with backcharge, warranty, insurance certificate, lien waivers), and one price box. Entering the sub's price there (`job.subPrice`) replaces the per-sq-ft cost. Never shows the customer's name/phone or your prices.
7. `#/settings`: company info, all unit prices, finish upcharges, guarantee %, warranty years, deposit split, bonuses.

Site plans (`sitePlanSVG()`) draw over Esri satellite tiles stitched by `satImage()` (cached in IndexedDB as `sat:<bounds>`; `hydrateSat()` fills them in, and Save PDF waits for it). Small pours get their letter badge beside them.

## Proposal extras
- Per-job **Customer price** (`job.price`, anchored to `job.priceFin`) and **On-time refund $** (`job.refund`) on the Proposal toolbar; other finish tiers keep the same ratio. `job.subFin` anchors the sub's price. The toolbar shows cost/profit and warns when the refund ≥ profit.
- Guarantee reads "started by … and finished by …"; without dates it says "the dates we agree on". `freeCancel` setting (default on) adds free cancellation before start.
- **Sign now** (`signModal()`): customer picks a finish, types name, signs with a finger (pointer events, works on phones); saved as `job.signed = {name, tier, total, sig (PNG), at, when}`, printed on the last page; sets `job.finish`. Remove from the toolbar.
- **Proof photos**: Settings card, stored in IndexedDB `proof:<id>`, list in `settings.proof`; up to 4 print on page 5. Backups carry them (`proof` map); a setup file (`{jobs, proof, proofCaptions, settingsPatch}`) imports without touching prices; `settingsPatch` only sets company, phone, email, license, freeCancel. Keep the owner's phone and customer data out of git (repo is public).

## Estimate math (see `estimate()`)
**Default: per-sq-ft pricing** (`pricingMode: 'sqft'`): each pour = area × installed rate for its thickness (owner's rates: 4″ $12, 5″ $14, 6″ $16; 8″ $20 is a placeholder; `sqftRate()`), plus tear-out (concrete/asphalt), pump/buggy and finish upgrades on top, `sqftMarkupPct` = owner's markup (default 0 → red "no profit" warning in the job header). The sq-ft rates are the owner's **costs** (what the sub charges, turnkey); `job.subPrice` overrides them once a sub quotes. Customer line items (`E.custLines`) have the markup built in — the proposal shows no markup line. No separate tax. Itemized mode below is still available in Settings.

Itemized: order yd³ = net × (1 + waste%), rounded up to 0.25 · short-load fee under N yd³ · pump/buggy per access · tear-out/sod per "now" · gravel tons = area × base/12/27 × 1.1 × 1.4 (reduced when reusing gravel) · fabric if soft soil · rebar $/sq ft · dowels if garage tie-in · forms $/lf of perimeter · labor $/sq ft · finish upcharge · tax on materials · markup on (subtotal + tax).
